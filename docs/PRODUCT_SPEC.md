# Zametnik — продуктовая спецификация

> Исходные требования заказчика. Не удалять и не сокращать смысл без явного согласования.

---

## 1. Общее описание концепции

Инструмент представляет собой **гибрид текстового блокнота (Markdown) и сетевой базы данных**. Вместо жёстких папок используется система двойных квадратных скобок `[[Ссылка]]`, которая связывает любые элементы (дни, задачи, мысли) в единую сеть. Пользователь может планировать неделю, связывая конкретный день с проектами, подзадачами, бытовыми заметками и людьми.

---

## 2. Сущности системы (типы заметок)

Вся система строится на **4 основных типах элементов**. Каждый элемент — отдельная текстовая заметка, которая может ссылаться на любую другую.

### 📅 Дневные заметки (Daily Notes)
- Создаются автоматически по шаблону: `ГГГГ-ММ-ДД` (например, `2026-08-31`)
- Являются «якорем» расписания на конкретный день

### 🛠 Задачи (Tasks)
- Объекты со статусом выполнения: `[ ]` — не сделано, `[x]` — сделано
- Могут жить внутри любого файла или быть отдельной заметкой

### 📂 Проекты / Контексты (Context/Project)
- Заметки, собирающие вокруг себя задачи по темам (например, `[[Проект Маркетинг]]`, `[[Здоровье]]`, `[[Покупки]]`)

### 🧠 Свободные заметки (Atomic Notes)
- Идеи, инсайты, справочная информация, мысли, возникшие в течение дня

---

## 3. Архитектура связей («ниточки»)

Система должна поддерживать **два типа связывания** — функционал «детективной доски»:

### А. Текстовые связи (вики-ссылки)

- Ввод `[[` открывает **автокомплит** (поиск по названиям существующих заметок)
- Пример планирования дня в ежедневной заметке:

```
09:00 — Созвон по [[Проект Альфа]] с [[Иван Иванов]].
12:00 — Написать структуру для [[Статья про ИИ]].
Сделать [[Задача: Купить подарок]].
```

- **Обратные ссылки (Backlinks):** если в заметке `2026-08-31` упомянут `[[Проект Альфа]]`, то внутри заметки «Проект Альфа» внизу автоматически отображается блок: «Упоминания: связано с заметкой 2026-08-31»

### Б. Визуальный холст (Canvas)

- Бесконечная двухмерная доска, куда пользователь может «вытащить» карточки дней недели (Понедельник, Вторник и т.д.) или карточки проектов
- Возможность **вручную соединять** их стрелочками разного цвета для наглядного таймлайна или цепочки зависимостей (например: `[Задача 1] ➡️ [Задача 2] ➡️ [Итог недели]`)

---

## 4. Сценарий: планирование недели

1. **Создание хаба недели:** заметка `[[Неделя 36 - 2026]]`
2. **Связывание дней:** внутри хаба — ссылки на 7 дней: `[[2026-08-31]]`, `[[2026-09-01]]` и т.д.
3. **Декомпозиция целей:** в хабе недели — глобальные фокусы (например: «Фокус недели: [[Запуск сайта]]»)
4. **Ежедневная работа:** утром открывается дневная заметка (например, `[[2026-08-31]]`). Она уже связана с «Неделей». Пользователь накидывает список задач на сегодня, тегая нужные проекты

## 5. Функциональные требования к интерфейсу

### Трёхпанельный интерфейс
| Панель | Назначение |
|--------|------------|
| **Левая** | Дерево файлов / список дней недели (быстрая навигация) |
| **Центральная** | Активный текстовый редактор Markdown (расписание) |
| **Правая** | Интерактивный локальный граф («мини-детективная доска») + список обратных ссылок |

### Graph View (общий граф)
- Отдельный **полноэкранный** режим: все заметки и задачи — узлы, связи — линии
- **Фильтрация:** подсветить только задачи, только определённый тег или только цепочку текущей недели

### Чекбоксы
- Быстрое переключение статуса задачи **кликом** или горячей клавишей **Ctrl+Enter**

## 6. Технологический стек (рекомендованный в ТЗ)

| Слой | Варианты |
|------|----------|
| Фронтенд | React.js, Vue.js или Svelte |
| Граф / Canvas | Vis.js, D3.js (force-directed), React Flow / Rete.js |
| Хранение (локальное) | Обычные `.md` в папке на устройстве; граф связей в памяти при запуске (как Obsidian) |
| Хранение (облачное) | NoSQL, например MongoDB — документы и связи |

## 7. Этапы разработки (MVP)

| Этап | Задача |
|------|--------|
| **1** | Текстовый редактор: Markdown + распознавание `[[имя_заметки]]` |
| **2** | Backlinks + автогенерация дневных заметок |
| **3** | Визуальный интерактивный граф (Graph View) |
| **4** | Canvas — ручное связывание карточек задач |

## 8. Дополнительные требования (второй запрос)

- Приложение должно быть **кроссплатформенным**
- В будущем — **связать ПК-версию и мобильную**, чтобы **план везде выглядел одинаково**
- **Настройка и управление** в приложении — **интуитивно понятные**
- Языки и стек должны **полностью закрывать** все перечисленные потребности

### Целевая архитектура (согласовано при проектировании)

| Слой | Выбор |
|------|-------|
| UI | React + TypeScript (единый код интерфейса) |
| Desktop | Electron (сейчас); миграция на Tauri 2 — когда установлен Rust |
| Mobile (будущее) | Tauri 2 mobile или Capacitor — тот же React UI |
| Граф | react-force-graph-2d |
| Canvas | React Flow (@xyflow/react) |
| Редактор | CodeMirror 6 |
| Данные | Local-first: `.md` + JSON-индекс |
| Sync (будущее) | Supabase / self-hosted — hash + timestamp, offline-first |

---

## 9. UX-принципы (не забывать при доработках)

1. **Первый запуск:** выбор папки vault — без обязательной регистрации
2. **Левая панель:** календарь недели + дерево «Проекты / Задачи / Недели»
3. **Правая панель:** мини-граф текущей заметки + backlinks (скрывается на узких экранах)
4. **Горячие клавиши:** `Ctrl+N`, `Ctrl+O`, `Ctrl+G`, `Ctrl+Enter`
5. **Мобильный (будущее):** те же 3 панели через drawer/tabs; canvas — pinch-zoom
